## 🎯 System Overview

**Garden TVET School Management System** is a comprehensive, ultra-advanced, full-stack school management platform designed specifically for managing three trades (AUT, BDC, SOD) across multiple levels (3-5) with advanced features for all stakeholders.

### **Key Features**
- ✅ **7 Ultra-Advanced Role Portals** with modern UI/UX
- ✅ **Real-time Notifications** via Socket.io + African Talking SMS
- ✅ **Auto-generation** of serial codes for student-parent linking
- ✅ **Automated Payment Reminders** (daily & weekly cron jobs)
- ✅ **Advanced Analytics** with Recharts visualizations
- ✅ **Content Management** for teachers (notes, works, holiday packages, quizzes)
- ✅ **Stock Management** with real-time inventory tracking
- ✅ **Auto-grading & Ranking** system
- ✅ **Global Student Sheets** accessible by all staff
- ✅ **Comprehensive Authentication** with role-based access control

## 🔐 Authentication & Authorization

### **Serial Code System** (`/api/serial-code-system`)
**Auto-Generation Format:**
```
{TRADE_CODE}{LEVEL}{SUFFIX}-{TIMESTAMP}-{RANDOM}
Example: AUT5A-K2J8X-A3F2B1
```

**Features:**
- Auto-generated when DOS adds student to global sheets
- One-time use for parent-student linking
- Expiration tracking (1 year validity)
- Status tracking (active, used, expired)
- Bulk generation support
- Regeneration capability

**Parent-Student Linking:**
- One parent per student (enforced by database constraint)
- Validation before linking
- Updates user's `linked_student_id` field

#### **1. global_student_sheets**
Central repository for all student data, accessible by all staff roles.

**Key Fields:**

- `payment_status` (paid, partial, unpaid)

#### **2. trades_levels**
Defines all trade and level combinations.

**Records:**
- BDC: Levels 3, 4, 5
- SOD: Levels 3, 4, 5
- AUT: Levels 3, 4A, 4B, 5A, 5B

#### **3. serial_codes**
Manages student serial codes for parent linking.

**Key Fields:**
- `serial_code`, `student_id`, `status`
- `generated_by`, `used_by`
- `generated_at`, `used_at`, `expires_at`

#### **4. parent_student_links**
Links parents to students (one-to-one).

**Key Fields:**
- `parent_id`, `student_id`
- `serial_code`, `linked_at`, `is_active`

#### **5. teacher_notes**
Stores study notes uploaded by teachers.

**Key Fields:**
- `teacher_id`, `title`, `description`
- `trade_code`, `level_number`, `level_suffix`
- `topic`, `category`, `files` (JSON)
- `status` (published, draft)

#### **6. teacher_works**
Manages assignments and class works.

**Key Fields:**
- `teacher_id`, `title`, `work_type`
- `total_marks`, `due_date`
- `submission_required`, `files` (JSON)

#### **7. holiday_packages**
Manages holiday learning packages.

**Key Fields:**
- `title`, `package_type`, `difficulty_level`
- `estimated_days`, `start_date`, `end_date`
- `files` (JSON), `instructions`

#### **8. quizzes & quiz_questions**
Quiz system with auto-grading.

**Key Fields:**
- `title`, `difficulty_level`, `time_limit`
- `total_marks`, `passing_marks`
- `randomize_questions`, `max_attempts`

#### **9. stock_items & stock_transactions**
Inventory management with transaction tracking.

**Key Fields:**
- `item_code`, `item_name`, `quantity`
- `reorder_level`, `supplier`, `location`
- `transaction_type` (purchase, issue, return, damaged, lost)

#### **10. realtime_notifications**
Real-time notification storage.

**Key Fields:**
- `user_id`, `title`, `message`, `type`
- `priority` (low, normal, high, urgent)
- `is_read`, `read_at`

## 🔄 Automation & Cron Jobs

### **Automated Tasks** (`backend/services/cronJobs.js`)

#### **1. Daily Payment Reminders (10:00 AM)**
```javascript
cron.schedule('0 10 * * *', ...)
```
- **Target**: Students with overdue balances
- **Actions**:
  - Send SMS via African Talking API
  - Send email notification
  - Create in-app notification
  - Log delivery status

**Message Format:**
```
GARDEN TVET: Dear [Guardian], your child [Student] ([Trade] L[Level]) 
has an outstanding balance of [Amount] RWF. Payment is [Days] days overdue.
```

#### **2. Weekly Payment Reminders (Monday 9:00 AM)**
```javascript
cron.schedule('0 9 * * 1', ...)
```
- **Target**: Payments due within 7 days
- **Actions**: Same as daily reminders

#### **3. Notification Cleanup (Daily Midnight)**
- Deletes notifications older than 90 days
- Keeps database optimized

## 🚀 Deployment Guide

### **Prerequisites**
- Node.js 16+ and npm/yarn
- MySQL 8.0+
- African Talking API credentials (for SMS)
- Email SMTP credentials

### **Environment Variables** (`.env`)
```env
# Database
DB_HOST=localhost
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=school_management

# JWT
JWT_SECRET=your_super_secret_key_change_this
JWT_EXPIRE=7d

# African Talking
AFRICAS_TALKING_USERNAME=your_username
AFRICAS_TALKING_API_KEY=your_api_key
AFRICAS_TALKING_SENDER_ID=GARDENTVET

# Email
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USER=your_email@gmail.com
EMAIL_PASS=your_app_password

# Server
PORT=5000
NODE_ENV=production
FRONTEND_URL=http://localhost:3000
```

### **Installation Steps**

#### **1. Backend Setup**
```bash
cd backend
npm install
node setup-trades-levels.js
node scripts/setup-serial-code-system.js
npm start
```

#### **2. Frontend Setup**
```bash
cd ..
npm install
npm run dev
```

### **3. Database Setup**
Run the following setup scripts in order:
1. `backend/setup-trades-levels.js` - Creates trades and levels
2. `backend/scripts/setup-serial-code-system.js` - Creates serial code tables

## 🔒 Security Features

### **1. Authentication**
- JWT tokens with expiration
- Password hashing with bcrypt (10 rounds)
- Token refresh mechanism
- Role-based access control

### **2. Rate Limiting**
- General: 100 requests/15 min
- Auth endpoints: 5 requests/15 min
- API endpoints: 200 requests/15 min

### **3. Input Validation**
- express-validator for all inputs
- SQL injection prevention (parameterized queries)
- XSS protection (input sanitization)
- File upload restrictions (type, size)

### **4. Database Security**
- Connection pooling
- Foreign key constraints
- Unique constraints (serial codes, emails)
- Cascade delete/update rules
